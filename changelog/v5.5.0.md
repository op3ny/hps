## Correções

### Bug #2 — "Criar API App" falhando com "Informe o hash do conteúdo do App."

**Sintoma:** ao usar a ação "Criar API App", a operação era rejeitada imediatamente com a mensagem "Informe o hash do conteúdo do App.", mesmo quando o usuário já possuía o conteúdo do App em cache.

**Causa raiz:** o painel `IsHpsActionApiCreate` em `MainWindow.axaml` continha apenas o campo "Nome do App". Não existia `TextBox` ligado a `HpsContentHash`. Como `ApplyHpsAction` exige `HpsContentHash` não vazio e com comprimento ≥ 32 (`MainViewModel.cs:3565`, ramo `Criar API App`), a propriedade permanecia vazia e a validação sempre retornava erro. O painel de transferência de arquivo (`transfer_api_app`), que compartilha a mesma exigência, já tinha o campo.

**Arquivos alterados:**

- `HPS-BROWSER/browser-cs/MainWindow.axaml` — adicionado o campo "Hash do conteúdo do App:" (`TextBox` `Width="420"`, `Text="{Binding HpsContentHash}"`) no painel `IsHpsActionApiCreate`, espelhando o padrão do painel de transferência de arquivo (`MainWindow.axaml:207-208`).

**Comportamento corrigido:**

- O `TextBox` preenche `HpsContentHash` via data-binding e a validação de `ApplyHpsAction` é satisfeita.
- A ação prossegue para `change_api_app`, como a transferência de arquivo já funcionava.

### Bug #1 — Câmbio (exchange) sem resposta após confirmar o valor

**Sintoma:** ao clicar em "Solicitar Cotação", o popup de valor abria; após confirmar, nada acontecia — sem cotação e sem erro. Manifestava-se com vouchers de servidor remoto/diferente.

**Causa raiz:** `MainViewModel.BuildVoucherDkvhpsDisclosure` chamava `CryptoUtils.DecryptOaepBase64` sobre `voucher_owner_encrypted`/`lineage_owner_encrypted`. `DecryptOaepBase64` lançava `ArgumentException` (entrada vazia) ou `CryptographicException` (ciphertext malformado). O `AsyncRelayCommand.ExecuteAsync` engolia exceções (só `Console.Error`), então a requisição de cotação nunca era emitida — falha silenciosa.

**Arquivos alterados:**

- `HPS-BROWSER/browser-cs/Services/CryptoUtils.cs` — `DecryptOaepBase64` retorna `string.Empty` em entrada vazia/whitespace, em vez de lançar.
- `HPS-BROWSER/browser-cs/ViewModels/MainViewModel.cs`
  - `BuildVoucherDkvhpsDisclosure` protege cada descriptografia com checagem de chave nula e `try/catch` (não lança mais).
  - `RequestExchangeQuoteAsync` envolvida em `try/catch` que exibe a falha em `ExchangeQuoteMessage`; adicionada checagem de divulgação DKVHPS (`se vazia ou não contiver "## ENTRY_"`) → mensagem `"Os vouchers selecionados não possuem divulgação DKVHPS necessária para o câmbio."`.

**Comportamento corrigido:**

- Vouchers com divulgação DKVHPS válida prosseguem para a cotação.
- Divulgação ausente/inválida exibe mensagem de erro visível (em vez de silêncio).

### Bug #3 — Paginação de contratos congelando em 50/1271

**Sintoma:** na aba Contratos, clicar em "Próximo" congelava a listagem (ex.: travada em "50/1271").

**Causa raiz:** `handleSearchContracts` (`internal/socket/server.go`) calculava `total` por `COUNT(1)` sobre a tabela inteira, mas filtrava em Go os contratos onde `ShouldHideReplicatedContract` era verdadeiro (`username` em `custody`/`system` **e** `verified = 0`). O `total` superestimava os contratos exibíveis; o cliente usava esse valor como `_contractServerTotalCount` e páginas além dos contratos visíveis retornavam vazias enquanto o `offset` avançava.

**Arquivos alterados:**

- `HPS-SERVER/server-go/internal/socket/server.go` — em `handleSearchContracts`, adicionada `hideClause := " NOT (LOWER(username) IN ('custody', 'system') AND verified = 0) "`, aplicada tanto à query de `COUNT` quanto à de dados (`WHERE` ou `AND`).

**Comportamento corrigido:**

- `total` reflete apenas contratos exibíveis; a paginação alcança o fim e o contador fica consistente.
- Teste de regressão `internal/socket/search_contracts_test.go` (`TestSearchContractsTotalExcludesHiddenReplicatedContracts`) adicionado: **passa com a correção** e **falha sem ela** (`total=13` vs esperado `8`).

## Build

### Servidor (Go)

`CGO_ENABLED=0` (driver `modernc.org/sqlite`, puro em Go — sem mingw/WSL). Cross-compile a partir de Windows:

```bash
# Windows
CGO_ENABLED=0 go build -o builds/hps-server-win64.exe .
# Linux
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o builds/hps-server-linux64 .
```

### Cliente (HPS-Browser, C#/Avalonia — `net8.0`)

`dotnet publish -c Release` (compila com **0 erros**; apenas *warnings* de nullable pré-existentes):

```bash
dotnet publish HpsBrowser.csproj -c Release -r win-x64  -o builds/hps-browser-win64
dotnet publish HpsBrowser.csproj -c Release -r linux-x64 -o builds/hps-browser-linux64
```

**Notas de runtime (Browser):**

- Os builds acima são **framework-dependent**: o alvo precisa do **.NET 8 runtime** instalado. Para self-contained (inclui o runtime), reconstrua com `--self-contained true`.
- No Linux, o binário `HpsBrowser` sai sem bit de execução no NTFS — rode `chmod +x HpsBrowser` ao copiar. Em runtime também são necessárias as libs de sistema do Avalonia (libX11, fontconfig, etc.).
